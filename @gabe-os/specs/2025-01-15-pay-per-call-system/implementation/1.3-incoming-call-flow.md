# Implementation Report: Task Group 1.3 - Incoming Call Flow

**Date:** 2025-01-15
**Tasks Completed:** P1-CF-1 through P1-CF-7, P1-CF-LOG-1

## Summary

Implemented the incoming call webhook handler, which is the entry point for all inbound calls to tracking numbers provisioned by the platform. This handler validates calls, creates records, and routes callers to IVR or auction.

---

## Files Created

### 1. `/src/app/api/calls/incoming/route.ts` (~200 lines)

**Purpose:** Twilio webhook handler for incoming calls.

**Key Features:**
- Twilio signature verification (security)
- Idempotency checking (prevents duplicate processing)
- Tracking number lookup with affiliate/campaign context
- Campaign eligibility validation (active, hours, caps)
- Call record creation in database
- TwiML response generation for IVR or direct auction path

**Call Flow:**
```
Caller dials tracking number
    |
    v
Twilio sends webhook to /api/calls/incoming
    |
    v
Verify signature + idempotency check
    |
    v
Lookup tracking number -> affiliate, campaign, service
    |
    v
Check campaign eligibility (active, hours, caps)
    |
    v
Create Call record (status: RINGING)
    |
    v
Return TwiML:
  - If IVR configured: redirect to /api/calls/ivr
  - If no IVR: redirect to /api/calls/auction
```

### 2. `/src/lib/services/call-eligibility-service.ts` (~200 lines)

**Purpose:** Campaign eligibility checks before accepting calls.

**Key Functions:**
- `checkCampaignEligibility()` - Main validation function
- `checkDailyCap()` - Query DailyCounter table
- `checkBuyerAvailability()` - Check if buyers exist for service/ZIP
- `incrementCallCounter()` - Atomic counter increment for cap tracking
- `isServiceTypeActive()` - Service type status check

**Eligibility Checks:**
1. Campaign active status
2. Business hours (timezone-aware)
3. Daily call cap enforcement
4. Buyer availability for service/ZIP (optional)

### 3. `/src/lib/call/call-helpers.ts` (~200 lines)

**Key Functions:**

## Design Decisions

### 1. Reused Existing Infrastructure

The implementation heavily reuses existing Twilio infrastructure:
- `withTwilioVerification()` from `src/lib/twilio/verify-signature.ts`
- `isWebhookProcessed()` from `src/lib/twilio/idempotency.ts`
- `logWebhookReceived()`, `createCallActivityLog()` from `src/lib/twilio/logging.ts`
- `buildIvrGather()`, `buildAnnouncement()`, `buildRejection()` from `src/lib/twilio/twiml-builder.ts`
- `getTrackingNumberByPhone()` from `src/lib/services/tracking-number-queries.ts`

### 2. Fail-Open Philosophy

For revenue-critical paths, the system fails open:
- If hours config parsing fails, allow the call
- If cap check fails, allow the call
- If buyer availability check fails, allow the call

This ensures legitimate calls are not blocked by edge cases.

### 3. Two Call Paths

The handler supports two distinct paths:
1. **IVR Path:** If campaign has `ivrFlowId` or tracking number has `ivrFlowId`, route to IVR
2. **Direct Auction Path:** If no IVR configured, skip qualification and go directly to auction

### 4. Comprehensive Logging

Every significant event is logged:
- Webhook receipt (via `logWebhookReceived()`)
- Eligibility check results
- Call record creation
- Activity logs visible to affiliates (via `createCallActivityLog()`)

## Error Handling

| Scenario | Response |
|----------|----------|
| Unknown tracking number | TwiML rejection with polite message |
| Campaign inactive | TwiML rejection |
| Outside business hours | TwiML with hours announcement |
| Daily cap reached | TwiML with "high volume" message |
| Database error | TwiML with generic error, log to Sentry |
| Duplicate webhook | Empty TwiML response (200 OK) |

## Testing Notes

To test locally:

1. **Expose local server via ngrok:**
   ```bash
   ngrok http 3000
   ```

2. **Configure Twilio webhook:**
   - Go to Twilio Console > Phone Numbers
   - Set Voice webhook to `https://<ngrok-url>/api/calls/incoming`

3. **Call a tracking number:**
   - Database must have a TrackingNumber record with matching phoneNumber
   - Call that number

4. **Verify in database:**
   ```sql
   SELECT * FROM calls ORDER BY created_at DESC LIMIT 1;
   SELECT * FROM call_activity_logs ORDER BY created_at DESC LIMIT 5;
   SELECT * FROM webhook_events ORDER BY processed_at DESC LIMIT 5;
   ```
